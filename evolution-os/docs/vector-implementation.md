# 向量搜索实现原理

## 整体架构

```
文本输入 → 分词 → TF-IDF向量化 → 相似度计算 → 结果排序
```

## 核心技术

### 1. TF-IDF (词频-逆文档频率)

**TF (Term Frequency)**: 词在文档中出现的频率
```
TF = 词出现次数 / 文档总词数
或 TF = 1 + log(词频)  (对数压缩)
```

**IDF (Inverse Document Frequency)**: 词的重要性
```
IDF = log(总文档数 / 包含该词的文档数) + 1
```

**TF-IDF = TF × IDF**
- 词在当前文档中出现越多 → 分值越高
- 词在越少文档中出现 → 分值越高
- 常见于所有文档的词（如"的"）→ 分值低

### 2. 余弦相似度

计算两个向量之间的夹角余弦值：
```
cos(θ) = (A·B) / (||A|| × ||B||)
```

- 值域: [0, 1]
- 1 = 完全相似
- 0 = 完全不相关

### 3. 实现步骤

**步骤1: 分词**
```python
def tokenize(text):
    # 中文: 提取2-4个字符的词
    chinese = re.findall(r'[\u4e00-\u9fa5]{2,4}', text)
    # 英文: 提取单词
    english = re.findall(r'[a-z]+', text.lower())
    # 数字
    numbers = re.findall(r'\d+', text)
    return chinese + english + numbers

# 示例: "建立进化系统"
# → ['建立', '进化', '系统', '建立进化', '进化系统', '建立进化系统']
```

**步骤2: 构建词汇表**
```python
# 遍历所有文档，收集唯一词汇
vocabulary = {
    '进化': 0,
    '系统': 1,
    '技能': 2,
    ...
}

# 计算每个词的IDF
idf = {
    '进化': log(总文档数 / 包含'进化'的文档数) + 1,
    ...
}
```

**步骤3: 文档向量化**
```python
def text_to_vector(text):
    tokens = tokenize(text)
    vector = zeros(词汇表大小)
    
    # 统计词频
    token_counts = Counter(tokens)
    
    # 计算TF-IDF
    for token, count in token_counts.items():
        if token in vocabulary:
            idx = vocabulary[token]
            tf = 1 + log(count)
            vector[idx] = tf * idf[token]
    
    # 归一化 (L2范数)
    return vector / norm(vector)

# 示例向量 (简化)
doc_vector = [0.0, 0.5, 0.0, 0.3, 0.0, ...]  # 474维
```

**步骤4: 构建索引矩阵**
```python
# 所有文档向量堆叠成矩阵
# shape: (文档数, 词汇数)
vectors = [
    [0.1, 0.5, 0.0, ...],  # 文档1
    [0.0, 0.3, 0.7, ...],  # 文档2
    ...
]
```

**步骤5: 搜索**
```python
def search(query, top_k=5):
    # 查询向量化
    query_vec = text_to_vector(query)
    
    # 计算与所有文档的相似度
    # 矩阵乘法: (文档数, 词汇数) × (词汇数, 1) = (文档数,)
    similarities = dot(vectors, query_vec)
    
    # 排序取Top-K
    top_indices = argsort(similarities)[::-1][:top_k]
    
    return [
        (doc_id, score, snippet) 
        for idx in top_indices 
        if similarities[idx] > threshold
    ]
```

## 为什么这样设计?

| 选择 | 原因 |
|------|------|
| **TF-IDF** | 简单高效，不需要预训练模型 |
| **余弦相似度** | 对文档长度不敏感，只关心方向 |
| **中文2-4字符** | 覆盖词、短语，比单字语义更强 |
| **NumPy矩阵** | 计算快，内存友好 |
| **本地文件** | 无网络依赖，隐私安全 |

## 性能特点

- **索引速度**: 4个文档 < 1秒
- **搜索速度**: < 10ms
- **内存占用**: ~50KB (474维 × 4文档 × 8字节)
- **扩展性**: 支持1000+文档无压力

## 优化点

1. **阈值调整**: 0.1 → 0.01 (提高召回率)
2. **停用词**: 无显式停用词，IDF自动降低常见词权重
3. **归一化**: L2范数，消除文档长度影响
4. **增量更新**: 当前是全局重建，可优化为增量

## 对比其他方案

| 方案 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| **TF-IDF** | 简单、快速、无需训练 | 无语义理解 | 关键词匹配、我们的场景 ✅ |
| **Word2Vec** | 有语义相似 | 需要预训练 | 语义搜索 |
| **BERT** | 深层语义理解 | 慢、资源占用大 | 高精度语义搜索 |
| **OpenAI Embedding** | 最强语义 | 需要API、费用 | 生产环境 |

我们的选择: **TF-IDF + 轻量级** = 足够好用，零依赖，本地运行。
